# Issue Investigation Report

Use to explain and resolve one concrete issue; use a retrospective instead when the main goal is organizational learning.

Path: symptom and impact → evidence → diagnostic reasoning → root cause → workaround and permanent fix → validation → prevention.

Required: summary/time/impact; symptom/evidence; key diagnostic path; evidence-backed root cause; temporary and permanent treatment; repair verification; prevention. Optional: timeline, quantified impact, tickets. Exclude raw logs/chat transcripts, unsupported cause guesses, and blame. Put reusable small troubleshooting in the relevant runbook instead.

Check: workaround and resolution are explicitly different and the cause has evidence.
