# Architecture Design / Technical Proposal

Use for an accepted design and its tradeoffs; do not use as a deployment runbook.

Path: goals and constraints → boundary/dependencies → solution and component duties → key runtime flows → deployment → decisions/tradeoffs → risk/evolution.

Required: goals/scope/quality objectives; constraints; system boundary; overview and component responsibility; key flows; deployment topology; core decisions; risks. Optional: data, security, availability, capacity, glossary, separate ADRs. Exclude daily commands, maintenance procedures, ungrounded selection, and future ideas presented as current facts. Use component, flow, and deployment diagrams when relevant; split independently maintained architecture views.

Check: diagrams, responsibilities, flows, topology, and decisions agree.
