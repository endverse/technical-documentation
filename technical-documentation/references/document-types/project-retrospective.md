# Project Summary and Retrospective

Use after a project or incident to learn and track improvement; do not use it as the current issue-resolution report.

Path: outcome/impact → factual timeline → causes and factors → effective/ineffective actions → learning → owned improvements → follow-up.

Required: background/goal/outcome; impact and factual timeline; causes/triggers/factors; what worked and did not; reusable learning; improvements with owner, priority, due date, and measurable done state; follow-up. Optional: metrics, stakeholder feedback, linked evidence. Exclude blame, diary-style narrative, and vague actions such as “improve communication”. Separate unrelated incidents.

Check: actions improve systems/processes and can be verified.
