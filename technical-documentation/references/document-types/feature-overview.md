# Feature Overview

Use to explain one feature or concept; do not use for a click-by-click task.

Path: what problem it solves → who/when it applies → how it works → boundaries, dependencies, and limits.

Required: positioning; audience/scenarios; core capability/workflow; boundaries/limits/dependencies. Optional: permission model, state/flow diagram, related features. Exclude UI steps, admin configuration, and multiple unrelated features. Split one concept per document; use an entry page for multiple features.

Check: it answers what and why without becoming a procedure.
