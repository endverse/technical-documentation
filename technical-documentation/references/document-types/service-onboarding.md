# Service Onboarding and Delivery Checklist

Use for shared service onboarding: requestor inputs, platform work, delivered outputs, and bilateral acceptance. It is the shared-role exception, not a long-term ownership handover or a full deployment plan.

Path: requested service → requestor materials → platform processing → platform outputs → bilateral acceptance → open items.

Required: scope/roles; requestor input list and completeness standard; platform tasks/owner/done condition; outputs/delivery method/use boundary; acceptance items/result; open risks/future owner. Optional: SLA/escalation, secure material-transfer method, linked deployment/user guide. Exclude secret values, detailed configuration steps, and responsibility-transfer wording. Use a responsibility/status table; use a flow only for complex approval/order.

Check: every role has unambiguous input, output, and completion condition.
